# Class League 기술 설명 (구조와 어려웠던 문제)

기능·규칙은 [SPEC.md](SPEC.md)에 있어요. 이 문서는 **그 규칙을 어떻게 구현했는지**, 특히 겉으로는 안 보이지만 직접 풀어야 했던 문제를 정리해요.

## 1. 한눈에 보는 구조

```
브라우저 (templates/ + static/css, static/js)
   │  fetch(JSON)                         ▲ 화면은 서버가 준 JSON만으로 그린다
   ▼                                      │
app.py ─ 앱 설정·보안(classleague/security.py)·Blueprint 연결
   │
classleague/routes/   auth · leagues · matches · admin · reports · notes · live · demo   ← API (권한·입력 검사)
   │
classleague/          engine (마감 정산·채점·재계산)  league_state (리그 상태 조회)
                      schedule (대진·일정 계산)       standings (순위)
                      clock (KST/UTC, '지금' 한 곳)   db (SQLite, 표·이전 버전 칸 추가)
   │
SQLite (app.db)
```

- **계산 코드는 DB 없이 돌아가게** 나눴어요. `schedule.py`는 날짜와 사람 목록만 받아 대진·일정을 돌려주므로 따로 시험할 수 있어요.
- **API 코드(routes)는 서로를 부르지 않아요.** 여러 곳에서 쓰는 것은 `engine`·`league_state`로 올렸어요.

## 2. 직접 풀어야 했던 문제

### ① 스케줄러 없이 마감을 자동 처리하기
- **문제:** 만들기·풀기 마감이 지나면 몰수 처리하고 다음 라운드로 넘어가야 해요. 그런데 마감마다 도는 예약 작업(cron)을 두면 서버가 꺼져 있던 사이의 마감을 놓치고, 배포 환경마다 설정이 달라져요.
- **해결:** **요청이 들어올 때 밀린 마감을 한꺼번에 정산**해요. 리그·경기를 다루는 모든 API 입구(12곳)가 먼저 `engine.refresh_league()`를 불러요.
  - 지금 시각과 저장된 마감 시각을 비교해 지난 경기만 규칙대로 끝내요 (`settle_deadlines`).
  - 마지막 풀기 마감이 지나면 리그를 '끝'으로 바꾸고, 그로부터 3일 뒤에는 남은 신고를 자동 확정해요 (`settle_reports`).
  - 여러 사람이 동시에 화면을 열어도 **한 번만 처리**되게, 쓰기 잠금(`BEGIN IMMEDIATE`)을 건 뒤 `... WHERE result IS NULL` 조건으로 고쳐요. 두 번째 요청은 고칠 것이 없어서 그냥 지나가요.
- **확인:** `test_draft_is_not_complete_and_forfeits_at_deadline`, `test_odd_league_runs_to_the_end_without_anyone_playing`

### ② 정답을 끝까지 비밀로 지키기 (개발자 도구로 봐도 안 보이게)
- **문제:** 화면에서 숨기기만 하면 브라우저 개발자 도구로 응답을 열어 정답을 볼 수 있어요. 경쟁 앱이라 치명적이에요.
- **해결:** **서버가 경기 단계와 사람에 따라 응답 자체를 다르게** 만들어요.
  - 풀기 화면 응답(`GET /matches/<id>/questions`)에는 정답·해설 칸이 아예 없어요. 정답은 제출 응답에서 처음 나와요.
  - 지난 경기 다시 보기는 경기 결과가 난 뒤(둘 다 제출했거나 마감으로 끝난 뒤)에만 정답을 줘요.
  - 관리자도 진행 중인 경기의 문제·정답은 못 봐요. 판정에 필요한 **신고된 문제만** 예외예요.
- **확인:** `test_full_round_grades_and_updates_standings` (응답에 `answer`·`explanation`이 없는지 검사), `test_admin_cannot_see_running_answers`

### ③ 버튼을 여러 번 눌러도 한 번만 처리하기
- **문제:** [제출]을 빠르게 두 번 누르면 "아직 안 냈나?" 검사를 두 요청이 동시에 통과해 두 번 채점될 수 있어요.
- **해결:** 검사하고 저장하는 API(19곳)는 **검사 전에 DB 쓰기 잠금**(`db.lock_db`)을 잡아요. 뒤에 온 요청은 앞 요청이 끝난 상태를 보고 "이미 제출했어요"를 받아요. 가입·리그 시작·신고 판정도 같은 방식이에요.
- **확인:** 두 번째 제출이 409를 받는지 검사

### ④ 대진표와 일정 계산
- **라운드 로빈:** 맨 앞 사람을 고정하고 나머지를 한 칸씩 돌리는 방식으로, N명이면 N−1(홀수면 N)라운드 동안 모두가 한 번씩 만나요. 홀수면 빈자리(None)를 넣어 라운드마다 한 명씩 쉬어요 (`schedule.make_round_robin`).
- **날짜:** 경기 요일(주 1~3회)로 라운드를 나누고, 라운드 앞쪽 절반을 만들기 기간으로 둬요. 어떤 라운드든 풀기 기간이 최소 하루 남게 검사해요 (`build_schedule`, `validate_make_days`).
- **시험 대비 단기 리그:** 종료 희망일 그날 마감까지 **완전히 끝나는 라운드 수**를 계산하고, 전체 대진의 앞부분만 써요. 그래서 같은 상대와 두 번 만나지 않아요 (`rounds_until`).
- **바로 보이는 미리 보기:** 리그 만들기 화면은 같은 규칙을 화면 쪽(`static/js/05-schedule.js`)에서도 계산해서, 설정을 바꾸는 즉시 라운드 수와 모든 마감을 보여 줘요.
- **확인:** `tests/test_schedule.py` (2~30명에서 모두가 한 번씩만 만나는지, 홀수 휴식, 단기 리그 라운드 수, KST→UTC)

### ⑤ 두 가지 순위 규칙과 공정한 계산
- 전체 리그는 승점 → 득실차 → 맞힌 수, 단기 리그는 **경기당 평균** 승점 → 평균 득실차 → 정답률이에요. 홀수 단기 리그는 쉬는 횟수가 달라 총점으로 비교하면 불공평하기 때문이에요 (`standings.compute_standings`).
- 몰수 경기는 경기 수와 승패에는 넣고 점수·득실차는 0:0으로 봐요.
- 전학 등으로 내보낸 학생과의 경기는 **양쪽 모두** 순위에서 빼요. 늦게 만날 차례였던 학생만 공짜 승점을 받는 일이 없게요.
- **확인:** `test_remove_student_mid_league_keeps_standings_fair`, `test_short_league_never_repeats_opponent`

### ⑥ 신고·무효와 다시 계산
- 무효 문제는 그 문제를 푼 학생에게 **1점을 인정**해요. 그냥 빼면 나쁜 문제를 받은 학생만 풀 문제가 줄어 불리하기 때문이에요.
- 점수는 "맞혔거나 무효인 문제 수"로 처음부터 다시 세고, 승패·순위·정답률·오답 노트가 모두 그 값을 따라가요 (`engine.recompute_match`).
- 판정 기한(리그 끝 + 3일)이 지나면 남은 신고는 '문제없음'으로 확정해요. 확인 안 된 신고로 점수가 바뀌면 신고를 남발해 이득을 볼 수 있어서예요.
- **확인:** `test_void_report_gives_point_and_recomputes`, `test_unjudged_report_becomes_ok_after_three_days`

### ⑦ 시간: 한국 시간으로 보여 주고 UTC로 저장
- 모든 마감은 한국 날짜·시각으로 정하고 DB에는 UTC로 저장해요. '23:59 마감'은 다음 날 0시 직전으로 다뤄요 (`clock.kst_deadline_utc`).
- 코드 전체가 '지금'을 `clock.now_utc()` 한 곳에서만 물어봐요. 덕분에 테스트에서 시계를 앞으로 돌려 **마감·몰수·리그 종료·판정 기한을 기다리지 않고** 확인해요.

### ⑧ 보안
- **로그인:** 비밀번호는 bcrypt로 저장해요. 5번 틀리면 1분 잠가요. 없는 아이디도 가짜 해시로 똑같이 검사해서 **응답 속도로 아이디가 있는지 알 수 없게** 했어요.
- **브라우저 보안 (`classleague/security.py`):**
  - CSP로 우리 사이트 파일만 실행해요. 그래서 화면에는 인라인 스크립트·style 속성을 두지 않아요. 테스트가 이것을 지켜요.
  - 다른 사이트 안에 넣기 금지, `nosniff`, `Referrer-Policy`, 쓰지 않는 기기 기능 끄기를 적용했어요.
  - 로그인 쿠키는 `SameSite=Lax`, `HttpOnly`예요. **https로 들어온 요청에만** `Secure`를 붙이는 작은 WSGI 미들웨어를 둬서, 배포(https)에서는 안전하고 내 컴퓨터(http)에서도 로그인이 돼요. 프록시 뒤에서는 `X-Forwarded-Proto`로 https를 알아봐요.
  - API 응답은 `no-store`라 같은 기기를 쓰는 다른 사람에게 남지 않아요. 2MB보다 큰 요청은 받지 않아요.
- **입력:** SQL은 모두 `?` 자리표시자를 써요. 글자는 화면에서 `textContent`로만 넣어 HTML이 실행되지 않아요. 이상한 JSON·목록·긴 글이 와도 500 대신 쉬운 안내를 돌려줘요.
- **확인:** `tests/test_security.py` (로그인 잠금, 권한, 이상한 입력 8가지 × 10개 API, 쿠키·헤더)

### ⑨ 앱처럼 설치 (PWA)와 오프라인
- 서비스 워커는 **화면 파일만 저장**하고 API 응답은 절대 저장하지 않아요. 경기·로그인 정보가 기기에 남지 않게요.
- 화면 파일도 항상 새로 받아 보고, 인터넷이 끊겼을 때만 저장한 것을 써요. 그래서 고친 화면이 바로 반영돼요.

### ⑩ 실시간 갱신 (SSE)
- **문제:** 선생님은 진행 상황을, 학생은 상대가 [완성]했는지를 계속 새로고침하며 확인해야 했어요. 마감이 지나도 누군가 화면을 다시 열기 전까지는 몰수·다음 라운드가 반영되지 않았어요.
- **해결:** 리그 홈을 열어 두면 브라우저가 `GET /leagues/events`에 연결해 두고(Server-Sent Events), 서버가 2초마다 리그의 **버전 값**을 계산해 바뀌면 알려요 (`classleague/routes/live.py`).
  - 버전 값은 경기 상태·점수, 지난 마감 수, 참가자, 신고, 제출 수, 출제 범위를 이어 붙여 만든 해시예요. 시간이 지나 단계가 바뀐 것도 변화로 잡아요.
  - 알림에는 **버전 값만** 담아요. 화면은 알림을 받으면 기존 API(`/leagues/mine` 등)로 다시 받으므로, 권한 검사와 정답 비공개 규칙이 그대로 지켜져요.
  - 볼 때마다 `refresh_league()`를 부르므로, **보는 사람이 있으면 마감이 지나는 즉시** 몰수·다음 라운드가 정산돼요 (①과 같은 잠금으로 한 번만).
  - 스트림은 요청 정보에 기대지 않아요. 사용자 번호만 미리 받아 두고 DB도 따로 연결해서, 연결이 길어도 다른 요청에 영향을 주지 않아요. 연결 하나는 5분까지이고, 끊기면 브라우저가 3초 뒤 다시 연결해요.
- **사용자가 하던 일 지키기:** 입력하던 내용이 있거나, 펼쳐 본 내용·확인 창이 있으면 화면을 덮어쓰지 않고 [새 소식이 있어요]만 띄워요 (`static/js/03-league.js`의 `canRedrawLeague`).
- **확인:** `tests/test_live.py` (로그인 필요, 상대 [완성] → 알림, 선생님 화면 알림, **마감이 지나면 스트림이 직접 몰수 정산**, 변화 없으면 알림 없음, 알림에 버전 말고 다른 내용이 없는지). 브라우저 두 개로 학생이 [완성]하면 선생님 진행 상황 표가 새로고침 없이 ⏳→✅로 바뀌고, 입력 중일 때는 입력값이 그대로 남는 것도 확인했어요.

### ⑪ 혼자 체험해 보기 (가상 친구와 시간 앞당기기)
- **문제:** 이 앱의 핵심(만들기 → 마감 → 풀기 → 채점 → 순위)은 학생이 2명 이상 있고 **마감 시각이 지나야** 볼 수 있어요. 처음 온 사람은 혼자서는 아무것도 해 볼 수 없었어요.
- **해결 (`classleague/demo.py`, `routes/demo.py`):**
  - 체험 리그는 `league.demo_owner_id`로 구별해요. 가상 친구·체험 선생님은 `user.demo_kind='bot'`인 보통 계정이라, **진짜 리그와 같은 코드(대진·채점·몰수·순위·신고)를 그대로** 지나가요. 체험만을 위한 다른 규칙이 없어요.
  - 가상 친구의 행동은 `engine.refresh_league()`에 한 줄로 끼워요. 체험 리그면 마감 정산 전에 `bots_act()`가 풀기 기간이 된 경기를 풀어 제출해요. 그래서 실시간 갱신(⑩)이나 다른 화면에서 리그를 열 때도 똑같이 동작해요.
  - **시간 앞당기기:** 서버의 시계는 바꿀 수 없으니, 반대로 **체험 리그의 모든 시각(라운드 시작·만들기 마감·풀기 마감·종료 시각)을 다음 마감까지의 차이만큼 당겨요**. 그러면 다음 마감이 '방금 지난' 것이 되고, 이어서 `refresh_league()`가 평소처럼 정산해요. 마감을 다 지나면 신고 판정 기한까지 당겨서 결과를 확정해요.
  - **선생님 화면 바꾸기:** 같은 체험 리그의 두 계정(체험하는 사람 ↔ 체험 선생님) 사이에서만 로그인을 바꿔요.
- **진짜 리그 보호:** 체험 API는 지금 리그가 체험 리그가 아니면 403이에요. 체험 리그 코드로 참가할 수 없고, 지난 리그 목록에서도 빠져요.
- **확인:** `tests/test_demo.py` 9개 (로그인 없이 시작, 한 라운드 끝까지, 미완성 몰수, 리그 끝·상품, 신고 판정 기한, 선생님 화면, 체험 끝내기 후 진짜 리그 참가, **진짜 리그 마감은 그대로**, 닉네임 겹침 없음). 브라우저로 처음 온 사람처럼 시작부터 끝내기까지 눌러 봤어요 (자동 조작 약 17초).

## 3. 테스트 방법
- `pytest`로 69개를 돌려요 (서버 코드의 83%를 실행해요). 시험마다 **빈 임시 DB**를 새로 만들고, **가짜 시계**로 시간을 옮기며, Flask 테스트 클라이언트로 브라우저가 보내는 것과 같은 요청을 보내요.
- 대진·일정 같은 계산은 DB 없이 함수만 시험하고, 경기 흐름·권한·신고는 API를 통해 끝까지 시험해요.

## 4. 화면 코드 구성
- `templates/index.html`은 뼈대만 있고 화면마다 `templates/partials/`를 붙여요.
- CSS·JS는 `static/css/01-…`, `static/js/01-…`처럼 **번호 순서대로** 불러와요. CSS는 뒤 파일이 앞 파일을 덮어쓸 수 있고, JS는 앞 파일에서 만든 함수를 뒤 파일이 쓰기 때문이에요.
- 프레임워크 없이 만들었어요. 서버가 준 JSON으로 DOM을 직접 만들어서 빌드 과정이 없고, 파일을 열면 바로 고칠 수 있어요.
